# Amethys Launcher 0.1.0 — first experimental public release

> **Release status:** published as the project's first public 0.1.0 version.
>
> **Maturity:** experimental prototype for testing and feedback only. This is not a finished product and is not recommended for everyday or production use.

## What this release represents

Version 0.1.0 is the first small public milestone of Amethys Launcher. It exposes an initial technical foundation so that the architecture and a limited set of basic workflows can be tested on Windows and Linux.

The project as a whole is still under development. This release does not mean that Amethys Launcher is complete, fully usable, broadly compatible or ready to replace existing game launchers. The command-line tools and core components are early building blocks, not a finished end-user application.

## What is included in this first test version

- Rust-based Amethys agent and `amethysctl` command-line client.
- Local IPC between the CLI and agent:
  - Windows named pipes with a restricted user/System ACL.
  - Linux Unix-domain sockets with user-only permissions.
- Local SQLite-backed game library and configuration.
- Initial, read-only discovery from supported launcher metadata:
  - Steam;
  - Epic Games Launcher on Windows;
  - Heroic / Legendary;
  - GOG Galaxy;
  - Amazon Games;
  - EA app on Windows;
  - Ubisoft Connect on Windows;
  - Battle.net on Windows;
  - Riot Games on Windows;
  - initial Xbox GDK detection on Windows.
- Explicit single-game and bulk import; discovery does not silently modify the Amethys library.
- Basic library listing, platform filtering, local search and removal.
- Read-only installation/executable verification.
- Launching an explicitly configured executable without invoking a shell, constrained to the registered installation directory.
- Automated Windows and Linux build/test CI and portable archive packaging.
- SHA-256 checksums for release archives.

This list describes implemented foundations and limited workflows, not a promise that every launcher, game or machine is fully supported.

## Important limitations

- **No graphical interface:** this release is command-line only.
- **Not production-ready:** reliability, compatibility, usability and real-world coverage remain incomplete.
- **No complete launcher experience:** there is no finished unified user interface or polished end-user workflow.
- **No store or catalogue:** users cannot browse or buy games through Amethys.
- **No game download or installation:** official launchers remain responsible for installing and updating games.
- **No account system, cloud save synchronization or backup feature.**
- **No automatic updates, service registration, autostart, desktop shortcut or uninstaller.**
- Discovery is metadata-based and read-only. It does not verify game-file integrity or guarantee that a detected game can launch.
- Real-install validation is not uniform across adapters. Consult [launcher discovery coverage](../discovery/LAUNCHER-COVERAGE.md):
  - Steam and Epic have local Windows real-install checks recorded.
  - EA app has a local Apex Legends/custom-library check recorded.
  - VALORANT has a local Riot installation check recorded; other Riot titles remain pending.
  - Battle.net has fixture/CI coverage but no recorded real-install validation.
  - Xbox GDK detection remains initial and requires real GDK installation validation.
  - Linux Steam discovery has fixture/CI coverage; real-machine validation remains pending.
  - Other adapters may be fixture-tested only; consult the coverage table.
- macOS is not a 0.1.0 target.
- Passing automated CI proves only the automated cases that were run. It does not prove universal hardware, launcher or game compatibility.

## What is planned after 0.1.0

The next stages are still being planned and developed. Broad directions include:

1. Stabilize and harden the existing core, IPC, database and configuration.
2. Expand automated tests and real-machine validation on Windows and Linux.
3. Improve launcher detection, compatibility reporting, error messages and diagnostics.
4. Refine the architecture and prepare the foundations for a more complete application.
5. Design and progressively develop a graphical interface.
6. Consider larger future components such as a game catalogue/store, downloads and installation workflows, accounts, backups and save synchronization.

These are development directions, not features included in 0.1.0 or guaranteed for a particular date. Their order and scope may change as testing and development progress.

## Security and privacy

Amethys does not bypass DRM, licensing, authentication, anti-cheat or platform restrictions. Discovery reads launcher metadata and does not modify game installations or launcher databases. IPC is local-only and must not be exposed over a network.

Do not send credentials, tokens, private launcher databases, personal paths or other sensitive diagnostics in public feedback. Redact usernames and private directory names from logs.

## Feedback

This release is intended to collect early testing feedback. Report reproducible bugs and compatibility observations through GitHub Issues, following the repository templates. Include operating system, launcher/version when known, exact Amethys command, expected/actual behaviour and sanitized output. Do not attach credentials or private platform data.

## Disclaimer

Use this experimental version only if you understand that it is early software and may contain bugs, incomplete behaviour or compatibility problems. Do not rely on it as the sole manager or launcher for your games. Keep using official launchers for installation, updates, authentication and licenses, and back up important data as a general precaution.
