# Amethys Launcher 0.1 pre-release checklist

This checklist is for the maintainer. A checked item must have evidence; do not mark a step complete based on intention alone.

## Repository and scope

- [x] Workspace version is `0.1.0`.
- [x] Windows x86_64 and Linux x86_64 are the declared 0.1 release targets.
- [x] macOS and the GUI/store/download/account/cloud-save features are explicitly out of scope.
- [x] Launcher discovery documentation separates fixture/CI evidence from real-install validation.
- [ ] Confirm the final release commit is the exact commit intended for the candidate tag.
- [ ] Confirm no credentials, tokens, private platform data, personal diagnostics or unintended generated files are present in the candidate diff.

## Automated quality and functional evidence

- [x] Latest main-branch CI passed on Ubuntu and Windows for commit `67dc5d5424acd7e98958072af0b36539a9b2c240` (2026-11-22).
- [x] CI runs formatting verification and Clippy with warnings denied.
- [x] CI runs workspace tests and release builds on both operating systems.
- [x] CI exercises agent/CLI IPC, status, scan, import/add, list, search, remove, verification and safe launch behaviour using controlled fixtures.
- [x] CI extracts platform archives and checks their contents, CLI version/help, agent startup, ping and status.
- [ ] Re-run CI after any subsequent code or workflow change and record the new run URL and commit.
- [ ] Confirm the release workflow itself completes successfully for the selected candidate tag.

## Release artifact checks

- [x] Release workflow targets Windows ZIP and Linux TAR.GZ.
- [x] Release workflow creates and verifies SHA-256 checksums.
- [x] Release workflow creates a GitHub draft rather than publishing automatically.
- [x] Release workflow supports semantic pre-release suffixes and marks suffixed tags as pre-releases.
- [ ] Create the candidate tag only after maintainer approval (proposed: `v0.1.0-pre.1`).
- [ ] Inspect both downloaded archives and confirm the two executables, README, LICENSE and RELEASES guide are present.
- [ ] Verify the published draft's tag, title, pre-release flag, assets and SHA-256SUMS.
- [ ] Manually publish the draft only after the maintainer explicitly approves publication.

## Documentation and known limitations

- [x] First-run instructions explain foreground agent startup and CLI use.
- [x] Release notes describe the CLI/core scope and excluded features.
- [x] Adapter-specific real-install limitations are disclosed.
- [ ] Update the draft notes if the actual candidate differs from the documented scope or evidence.
- [ ] Review incoming security/compatibility reports before any stable 0.1.0 release decision.
